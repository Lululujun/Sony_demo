# v3 RFP Demo 设计自查表

## 1. 全局设计约束

| 检查项 | 自查标准 |
|---|---|
| 暖 stone + 白卡体系 | 沿用 lite 的 stone token、白色卡片和点阵背景，不新增独立品牌色 |
| 中文业务标题 | 页面只保留中文产品标题，不增加大写英文装饰标题 |
| 无常驻口号 | 说明进入帮助气泡、字段注释或 trace，不占据主视觉区域 |
| 字体与数字 | 正文使用 Inter/系统中文字体；核心数字使用 JetBrains Mono 与 tabular numerals |
| 颜色语义 | 蓝色表示主流程/公平，绿色表示完成/效率，橙色表示阈值/关注，红色表示高风险 |
| 深色元素 | 仅允许用于工作台展开后的单户求解轨迹、智能分层底部决策轨迹、比例页展开后的计算轨迹；禁止全高深色侧栏 |
| 轨迹宽度契约 | `row` 变体仅用于可用宽度不小于 720px 的横向结果区；更窄或跨页解释场景统一使用底部 `band` 变体 |
| 确定性截图 | `shot=1` 固定时间和数据状态，隐藏 Toast、重置按钮及滚动条 |
| 投影适配 | 1280×720 下不裁掉关键操作；低于 1440px 时降低密度，不缩小核心数字 |
| 可访问性 | 所有图标按钮有 `aria-label`；状态不只依赖颜色；表单具备可见标签 |

## 2. 六页视觉主角

| 页面 | 单屏视觉主角 | 应避免 |
|---|---|---|
| 智能分层 | 六级停靠树与当前展开路径 | 同时平铺 50 个节点造成拥挤 |
| 分货工作台 | 横向分配轨道与回放进度 | 把字段解释写成大段方案文案 |
| 方案对比 | 三方案卡与逐经销商变化图 | 三张内容完全相同的静态卡 |
| 比例与特殊物料 | 三维 ratio 汇聚与多色总量校验 | 将比例、特殊物料拆成互不关联的宣传模块 |
| 周转与校准 | PSI sellout 周转与置信区间 | 继续把库存流量法放在主指标位置 |
| 后台管理 | 八项配置 + 诊断/留痕双栏 | 复制传统后台的高密度全量菜单 |

## 3. 智能分层

- 默认只展开当前判断路径，其他分支保持概览或折叠。
- 六级名称固定为总部、渠道、子渠道、大区、分公司、经销商。
- 停靠节点使用实心蓝色和明确文字“停靠”。
- 继续下沉节点展示满足度与阈值差距。
- 上游已停靠的下游节点灰显，并显示“上游已停靠，可直接下单”。
- P1/P2 场景按钮位置固定，切换后树、指标和 trace 同步变化。
- 阈值滑杆不遮挡树；经销商终点显示为不可调整。
- 决策轨迹位于树下方并默认展开，不再占用右侧窄栏；点击轨迹步骤可定位并高亮完整祖先路径。

## 4. 分货工作台

- MIA、SAP、SSP 来源标签靠近 SKU，不作为页面口号。
- 轨道静止态同时展示需求、额度、公平量、效率量、最终量和适用的周上限。
- 大客户徽标与“豁免周上限”必须同时保留资金约束说明。
- Skip 命中时使用明确的禁用态和转 SSP 提示，不只把按钮变灰。
- 回放事件横向滚动但隐藏突兀的滚动条，滚轮/触控板仍可使用。
- 左侧参数区隐藏滚动条外观但保留滚动能力。
- RFC 按钮使用完整业务名称，避免误解为已连接真实系统。

## 5. 比例与特殊物料

- 三个分项横条长度、最终 ratio 和 trace 使用同一组实时结果。
- 权重合计不为 1 时显示“将正规化”，不能伪装成已校验通过。
- 大客户状态、`kBig`、计划参考、额度上限在同一信息区出现。
- 直营、Buffer、其他渠道池按固定三步顺序展示。
- 多色区域始终显示型号合计与整体上限校验。
- 单色超过自身目标使用橙色提示，不使用错误态红色。
- Skip 清单支持键盘添加和可识别的删除按钮。
- 计算轨迹位于页面底部并默认折叠；展开后使用横向审计带，不与 PIC 参数区争抢宽度。

## 6. 周转与校准

- 主指标标题明确写出“sellout 消化周转周期”。
- 平销期/大促期切换与周均 sellout 同屏。
- 置信区间采用浅蓝低透明度，不遮挡估算线和真值点。
- 库存流量法放入“交叉校验”小卡。
- “无法估算”以文字显示，不显示 `Infinity`、`NaN` 或误导性的 0 周。
- 校准结果同时表达偏差数值、可信度和下一轮动作。

## 7. 后台管理与诊断

- 八项配置以紧凑卡片组织，1280 宽度下保持两列或单列自然降级。
- 配置版本号在页面标题区持续可见。
- 每次配置修改都能在变更留痕中看到旧值、新值、操作人、时间和版本。
- 回滚按钮在没有历史版本时禁用。
- 提示词区域必须显示“只影响解释，不参与计算”。
- CSV 下载按钮与记录表放在同一张卡片。
- 三类诊断分别使用类别标题，告警级别使用状态签和文字。
- 参数快照默认折叠，证据保持可扫描。
- 只有存在 `drillDownRef` 的告警显示“下钻到轨迹”。

## 8. 图表与表格

| 元素 | 规范 |
|---|---|
| Recharts 网格 | stone 横向网格，避免密集纵网格 |
| 刻度 | JetBrains Mono、小号 stone 文本 |
| Tooltip | 白底、stone 边框、圆角，不使用深色悬浮框 |
| 表格数字 | 右对齐或统一等宽，表头不换行 |
| 状态签 | 使用现有 `StatusPill` 色阶 |
| 空状态 | 写清原因和下一步，不只显示空白图标 |

## 9. 文案校验

- 讲算法和操作，不复述 PPT 章节标题。
- “数据来源”与“系统已连接”严格区分。
- “模拟 RFC”与“真实回写”严格区分。
- “大客户豁免周上限”不得简写成“无上限”。
- “PA Plan Ratio”首次出现时必须说明三个分项。
- “PSI 周转”首次出现时必须说明当前库存与周均 sellout。
- “提示词”必须说明不影响计算。
- 页面、README、演示脚本和用户说明采用同一套字段名称。

## 10. 验收截图

建议至少检查以下画面：

1. P1 总部停靠；
2. P2 渠道 A 停靠、其余下沉；
3. 工作台 108/50/52 完成态；
4. 单户求解轨迹展开；
5. 三方案对比；
6. PA Plan Ratio 三维合成；
7. 多色 12+8=20 收口；
8. PSI 平销/大促周转；
9. 三类诊断与参数快照；
10. 配置变更留痕和回滚。

每张截图需分别在 1920×1080 和 1280×720 检查关键字段、按钮、状态签与表格是否完整可见。项目提供自动布局门禁：

```powershell
pnpm run check:shots
```

该命令覆盖 9 个确定性 preset × 2 个分辨率，共 18 个页面状态，并检查横向溢出、关键区域裁切、轨迹行数及 PPT 基线数据。
