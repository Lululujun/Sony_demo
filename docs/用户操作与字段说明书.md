# 索尼产品动态分配 Agent Demo · 用户操作与字段说明书

## 1. Demo 演示范围

本 Demo 演示一条完整的产品分配决策链：

```text
读取 MIA / SAP / SSP 数据
→ 判断应在哪个组织层级停靠
→ 计算 PA Plan Ratio 与业务约束
→ 运行公平层和效率层
→ 预演方案
→ 处理多色与 Skip
→ 分析 PSI 周转
→ 输出诊断、配置版本与审计记录
```

页面不是方案 PPT 的网页化复述。输入变化会调用真实前端纯函数，分配量、比例、trace、诊断和 CSV 都会重新生成。

当前数据为演示数据，不代表索尼真实经营数据；页面不会访问真实 MIA、SAP 或 SSP。

## 2. 三系统字段来源

| 数据来源 | 主要字段 | 在 Demo 中的用途 |
|---|---|---|
| MIA | 月度目标、产品计划、产品组 | Wkly Ratio 基数、目标需求 |
| SAP | 到货/可分货量、订单、库存、货款余额、主数据 | 分层与分货输入、资金硬约束、RFC 执行演示 |
| SSP | 过去 12 个月 PSI、周度 sellout、周初真值 | 周转主口径、库存校准、Skip 人工承接 |

工作台中的来源标签用于说明口径。正式接入时，应同时保存来源系统、采集时间、快照版本和数据质量状态。

## 3. 全局导航与顶部操作

### 3.1 六页导航

| 页面 | 用途 |
|---|---|
| 智能分层 | 决定供给停在总部、渠道或更低层级 |
| 分货工作台 | 查看和回放逐经销商分配 |
| 方案对比 | 比较三套业务取向 |
| 比例与特殊物料 | 调整比例规则、多色和 Skip |
| 周转与校准 | 查看 SSP PSI 周转与库存可信度 |
| 后台管理 | 管理配置、诊断、审计、权限和导出 |

六页共享同一 Context。修改比例、Skip、大客户或阈值后，其他相关页面会读取同一份配置。

### 3.2 场景与 SKU

场景是一组业务环境假设；SKU 是该场景下一个完整的产品快照。场景和 SKU 不是一一对应。

切换 SKU 会同时更新：

- 可分货量；
- 经销商集合；
- 需求、资金上限、履约权重和动销；
- 库存与可信度；
- MIA 月度目标和 SSP PSI；
- 分配结果、方案指标与诊断上下文。

PPT 示意场景的 WH-1000XM6 固定复现 A/B/C = 108/50/52。其他 SKU 使用独立数据，不会只改变页面标题。

### 3.3 触发分货

| 触发类型 | 含义 |
|---|---|
| 到货触发 | 模拟可分货实物到达后立即启动 |
| 定时批量 | 模拟定时任务按批次处理多个计划 |

点击“触发分货”后，页面依次执行数据校验、分层、比例计算、求解和诊断。两种类型使用同一算法，区别在于业务入口和执行记录。

### 3.4 日期与周初真值

顶部日期是模拟业务日期。点击“至下周一”会推进到下一个周初真值日，并打开校准流程。它不会连接外部日历或真实库存系统。

## 4. 智能分层

### 4.1 六级组织

| 层级 | 英文 ID | 说明 |
|---|---|---|
| 总部 | `hq` | 全国总计划 |
| 渠道 | `channel` | 直营、区域经销、电商等一级渠道 |
| 子渠道 | `subChannel` | 渠道内部业务形态 |
| 大区 | `region` | 区域经营单元 |
| 分公司 | `branch` | 具体运营与管理单元 |
| 经销商 | `dealer` | 最小自动分配颗粒度 |

### 4.2 节点字段

| 字段 | 含义 |
|---|---|
| 目标需求 | 该节点对应子树的计划目标 |
| 有效净需求 | 目标需求扣除已分配和在途后的实际缺口 |
| 历史达成度 | 用于解释经营状态，不在净需求之外再次重复扣减 |
| PA Plan Ratio | 同级子节点分摊供给时的相对比例 |
| 当前分配 | 上层传递到该节点的整数数量 |
| 满足度 | 当前分配 / 有效净需求 |
| 停靠阈值 | PIC 配置的最低满足度 |

### 4.3 停靠逻辑

```text
满足度 ≥ 本层阈值
→ 停靠在本层

满足度 < 本层阈值
→ 按子节点 PA Plan Ratio 分摊
→ 继续判断下一层
```

经销商为最小颗粒度，必定成为终点。已经在上游停靠的分支，其下游节点灰显并提示“上游已停靠，可直接下单”。

### 4.4 P1 与 P2

| 场景 | 供需特征 | 预期结果 |
|---|---|---|
| P1 货源充足 | 总部满足度达到 100% 阈值 | 总部停靠，下游不再细分 |
| P2 货源偏紧 | 总部未达阈值 | 渠道 A 可停靠，其他渠道继续下沉 |

调整阈值会立即重算树和页面底部的 Agent 决策轨迹。轨迹逐步显示节点、分配量、净需求、满足度、阈值、停靠/下沉理由及子节点份额。轨迹默认展开，可折叠；点击任一步骤会在六层停靠树中定位并高亮其完整祖先路径。

### 4.5 整数分摊

```text
子节点精确份额 =
  父节点分配量 × 子节点 PA Plan Ratio ÷ 同级 Ratio 合计
```

精确份额先向下取整；尾差按小数余数降序分配，余数相同按节点 ID 升序。停靠前沿合计始终等于输入供给。

## 5. 分货工作台

### 5.1 输入字段

| 字段 | 单位/范围 | 含义 |
|---|---|---|
| 今日可分货量 | 台，非负整数 | 当前 SKU 本轮可使用供给 |
| 需求 | 台，非负整数 | 经销商基础需求 |
| 额度 | 台，非负整数 | 当前货款余额按 SKU 单价折算的最大承接量 |
| 权重 | 无量纲 | 公平层中的履约相对权重 |
| 动销 | 无量纲指数 | 效率层中的销售与消化能力 |
| 公平预算 β | 0–1 | 基础上偏向公平覆盖的比例 |
| 淡旺季系数 | 常用 0.7–1.4 | 旺季提高效率倾向，淡季提高公平保护 |
| 市场缺货度 | 0–1 | 越稀缺越提高公平池保护 |

### 5.2 额度

页面以“台”为单位，是已折算的硬上限：

```text
额度折算数量 = floor（当前可用货款余额 ÷ 当前 SKU 含税单价）
```

任何分配层都不能突破额度。正式页面可以同时显示金额，但求解器必须使用整数件数。

### 5.3 履约权重

权重不是百分比，也不是最终台数。公平层有效权重为：

```text
需求 × 履约权重
```

权重可由历史达成、付款及时性、预测准确率等数据形成。Demo 使用一个可编辑综合值。

### 5.4 动销

动销是相对指数，不是“每天卖几台”。效率层权重为：

```text
动销 × 淡旺季系数 × 库存健康倍率
```

库存健康倍率：

| 状态 | 倍率 |
|---|---:|
| 断货风险 | 1.20 |
| 健康 | 1.00 |
| 积压 | 0.65 |

### 5.5 公平池

```text
缺货调整后公平比例 =
  β + 缺货度 ×（1 − β）

最终公平比例 =
  clamp（缺货调整后比例
  + clamp（(1 − 淡旺季系数) × 0.1, −0.1, 0.1）, 0, 1）

公平池 = round（可分货量 × 最终公平比例）
效率池 = 可分货量 − 公平层实际分配
```

缺货度高时提高基本覆盖保护；旺季在此基础上适度增加效率倾斜。

### 5.6 公平层与效率层

公平层：

```text
公平分配_i(λ) =
  min（需求_i, 有效硬上限_i,
       λ × 需求_i × 履约权重_i）
```

效率层：

- 仅接受库存可信的经销商；
- 按动销、季节和库存健康分配剩余量；
- 可以超过基础需求；
- 不能突破资金和适用的 Wkly Ratio 上限。

### 5.7 Wkly Ratio 与大客户

普通客户：

```text
本周上限 = floor（月度目标 × Wkly Ratio）
```

大客户：

- 不受本周硬上限限制；
- `kBig` 用于形成计划参考和策略得分；
- 仍受额度、库存、总供给和整数守恒限制。

### 5.8 横向轨道

| 图形 | 含义 |
|---|---|
| 蓝色段 | 公平层分配 |
| 绿色段 | 效率层追加 |
| “需求”竖线 | 基础需求位置 |
| “额度”竖线 | 资金硬上限 |
| “本周上限” | 普通客户 Wkly Ratio 约束 |
| 右侧台数 | 当前回放帧或最终分配 |
| 右侧百分比 | 单户最终分配 / 需求，可超过 100% |

### 5.9 顶部指标

| 指标 | 计算口径 |
|---|---|
| 可分货量 | 当前 SKU 供给池 |
| 覆盖经销商 | 最终分配大于 0 的经销商数 / 总数 |
| 需求满足率 | `Σmin（最终分配, 需求）÷ Σ需求` |
| 未分配供给 | 全部可承接去向封顶后剩余的数量 |

整体需求满足率不会超过 100%；单个经销商可能因效率加配超过 100%。

### 5.10 结果标签

| 标签 | 触发条件 | 含义 |
|---|---|---|
| 分配完成 | 获得分配且未触达特殊限制 | 正常完成 |
| 效率加配 | 最终量大于需求 | 获得效率层额外倾斜 |
| 额度触顶 | 最终量达到资金上限 | 资金是当前主要限制 |
| 周上限触顶 | 普通客户达到 Wkly Ratio 上限 | 本周计划限制生效 |
| 大客户 | 经销商配置为大客户 | 豁免周上限，但不豁免资金 |
| 仅保底 | 库存数据不可信 | 只参与公平层 |
| Skip | 当前物料命中清单 | 停止自动求解，转 SSP |
| 守恒校验通过 | 总量、上限、整数检查均通过 | 输出满足硬约束 |

### 5.11 分配明细与 trace

| 列 | 含义 |
|---|---|
| 经销商 | 名称和 ID |
| 需求 | 基础需求 |
| 额度 | 资金折算上限 |
| 公平层 | 公平水位分配 |
| 效率层 | 效率追加 |
| 最终分配 | 公平层 + 效率层 |
| 满足率 | 最终分配 / 需求 |
| 展开按钮 | 查看完整审计轨迹 |

主要事件：

- 创建供给池；
- 经销商进入或退出求解；
- 比例注入；
- 整数尾差分配；
- 需求、资金或周比例封顶；
- 库存不可信，仅保留公平层；
- 池量用尽或产生未分配供给；
- 输出最终结果。

### 5.12 RFC 回写

“调用 SAP 产品分配 RFC 回写”在 Demo 中只生成确定性执行结果和诊断状态，不发送网络请求。正式环境应由后端代理持有凭据、调用 SAP，并返回任务 ID、状态和 traceId。

## 6. 方案对比

三套方案使用相同的 SKU、供给、需求和硬约束，主要改变公平预算 β：

| 方案 | β | 业务倾向 |
|---|---:|---|
| 方案 A · 偏公平 | 0.9 | 提高基础覆盖 |
| 方案 C · 均衡 | 0.7 | 兼顾覆盖与效率，默认推荐 |
| 方案 B · 偏效率 | 0.5 | 更多供给进入效率层 |

指标：

- 覆盖经销商；
- 预计缺货率；
- 周转指数；
- HHI 分货集中度；
- 公平层占比；
- 额度利用率；
- 单户在三套方案中的最大差异。

点击“采用此方案”会把对应参数同步到工作台。所有方案仍执行相同硬约束。

## 7. 比例与特殊物料

### 7.1 PA Plan Ratio

三个分项：

| 分项 | 输入 |
|---|---|
| 供需态势 | 供给、净需求、覆盖率、缺货度 |
| 经营状态 | 订单、库存、额度覆盖、周转速度 |
| 策略配置 | Wkly Ratio、大客户 `kBig`、直营 Buffer |

```text
PA Plan Ratio =
  供需得分 × 正规化供需权重
  + 经营得分 × 正规化经营权重
  + 策略得分 × 正规化策略权重
```

页面三个横条显示分项得分，最终 ratio 在汇聚区显示；页面底部的“计算轨迹”默认折叠，展开后以横向审计带解释每个归一化和加权过程。

### 7.2 直营优先 + Buffer

```text
直营分配 = min（总供给, 直营需求）
可预留余额 = 总供给 − 直营分配
Buffer = floor（可预留余额 × Buffer Ratio）
其他渠道池 = 可预留余额 − Buffer
```

三段总和等于总供给。

### 7.3 同型号多色

| 字段 | 含义 |
|---|---|
| 物料代码 | 单个颜色物料 |
| 型号 ID | 多个颜色共同归属的型号 |
| 颜色目标 | 单色计划参考 |
| 过去 3 个月 DO | 拆分权重 |
| 分配量 | 按 DO 比例和整数规则得到 |
| 超自身目标 | 单色超过颜色参考，不代表型号超限 |

```text
型号可分总量 = min（可用量, 型号整体目标）
```

单色允许超自身目标，型号合计必须收口。默认 P1/P2 示例为 12+8=20。

### 7.4 Skip 清单

- 输入物料代码后按 Enter 或点击添加；
- 物料代码忽略前后空格和大小写；
- 命中当前 SKU 时，工作台停止自动求解；
- 从清单移除后，当前 SKU 恢复自动分配资格；
- 变更会进入后台配置版本。

## 8. 周转与校准

### 8.1 SSP PSI 主口径

每个经销商保存过去 52 周 sellout，并标记平销期或大促期。

```text
平销期周均 sellout =
  平销期 sellout 合计 ÷ 平销周数

大促期周均 sellout =
  大促期 sellout 合计 ÷ 大促周数

消化周转周期 =
  当前 PSI 库存 ÷ 当前时期周均 sellout
```

“平销期 / 大促期”切换会改变周均 sellout 和主周转指标。

### 8.2 库存流量交叉校验

```text
估算去货量 =
  期初库存 + 本期分货 − 期末库存
```

它用于验证 PSI 结果是否存在明显口径冲突，不再作为周转主指标。

### 8.3 置信区间

```text
日库存估算 =
  最近周初真值 + 累计分货 − 累计估算去货
```

- 深色点：库存真值；
- 蓝色虚线：每日估算；
- 浅蓝带：置信区间；
- 上界用于补货判断；
- 下界用于保供判断。

距离真值日越远，区间越宽。

### 8.4 周初校准

- 偏差在阈值内：保留可信状态并小步调整动销；
- 偏差超过阈值：标记库存数据不可信；
- 应用后同步更新库存、健康度、动销和下一轮分配资格。

## 9. 后台管理

### 9.1 八项配置

| 配置项 | 操作 |
|---|---|
| Wkly Ratio | 按产品组输入比例，标记每月 1 号生效 |
| 大客户管理 | 切换经销商 Flag，设置 `kBig` |
| Skip 清单 | 新增或删除物料代码 |
| 多色规则 | 调整型号/颜色映射和 3 个月 DO |
| 提示词 | 编辑解释风格；不进入计算 |
| 参数权重 | 调整 PA Plan Ratio 三维权重 |
| 分配记录 | 查看并导出 UTF-8 CSV |
| 用户权限 | 查看 PIC/业务/只读角色矩阵 |

### 9.2 配置版本和留痕

每次配置提交都会记录：

- 时间；
- 操作人；
- 配置字段；
- 旧值与新值；
- 新版本号。

“回滚到上一版”恢复上一份完整配置，而不是只恢复当前控件。回滚动作也会形成新的审计记录。

### 9.3 提示词边界

提示词只影响 Agent 对 trace 和诊断的语言表达，不会修改：

- 停靠判断；
- PA Plan Ratio 数值；
- 分配结果；
- 资金与周比例约束；
- PSI 周转；
- 诊断触发条件。

### 9.4 CSV

CSV 在浏览器内真实生成，包含配置版本、SKU、经销商、需求、额度、公平层、效率层、最终分配和满足率。文件带 UTF-8 BOM，可直接使用 Excel 打开。

## 10. 三类诊断

### 10.1 数据类

| 检测 | 说明 |
|---|---|
| 缺数 | 必填源字段为 `undefined` |
| 净需求异常 | 节点净需求小于 0 |
| 采集超时 | 当前时间减采集时间超过允许时效 |

### 10.2 结果类

| 检测 | 说明 |
|---|---|
| 满足度骤降 | 较上一轮下降超过配置阈值 |
| 集中度过高 | HHI 超过配置值 |
| 分配为零 | 符合条件且未被 Skip 的经销商最终为 0 |

HHI：

```text
HHI = Σ（经销商分配量 ÷ 总分配量）²
```

### 10.3 执行类

| 检测 | 说明 |
|---|---|
| RFC 失败 | 确定性模拟的执行状态为失败 |
| 任务超时 | 当前时间超过开始时间 + 超时阈值 |
| 重试耗尽 | 重试次数达到上限仍未成功 |

执行失败使用固定 seed 和稳定哈希，因此同一输入可复现。

### 10.4 告警卡片

每张卡包含级别、标题、详情、参数快照和证据。存在 `drillDownRef` 时，“下钻到轨迹”会切到分货工作台或智能分层，并展开对应 trace。

## 11. 常用按钮

| 按钮 | 行为 |

| 分步 | 每次推进一条事件 |

## 14. 常见问题

### 为什么最终分配可以高于需求？

需求是公平层的基础线。效率层可以给动销快、库存可信的经销商追加数量，但不能突破资金和适用的周比例上限。

### 为什么缺货度越高，公平池反而越大？

极度缺货时若只按效率集中，部分渠道可能完全断供。缺货度用于提高基本覆盖保护。

### 为什么大客户没有本周硬上限？

RFP 规则允许大客户豁免 Wkly Ratio，但它仍受货款余额、库存、供给总量和整数性约束。页面会同时显示计划参考和资金上限。

### 为什么某个分支在渠道层就停止？

该渠道获得的供给与有效净需求之比已达到 PIC 阈值。继续拆到更低层没有必要，可在该层形成订单。

### 为什么单个颜色可以超过自己的目标？

颜色目标是参考；多色规则以型号整体目标收口。某颜色 DO 更强时可以多分，但所有颜色合计不能超过型号上限。

### 为什么 Skip 物料没有结果？

命中 Skip 清单表示该物料不适合自动规则，系统主动停止求解并转 SSP 人工分配。

### 为什么平销期和大促期周转不同？

两种时期使用不同的历史周均 sellout。大促期销量通常更高，相同库存的预计消化时间会更短。

### 为什么修改提示词不会改变数字？

提示词与计算隔离，只控制解释方式。所有数字来自纯函数和配置参数。

### 为什么刷新页面后演示状态恢复？

当前 Demo 不连接数据库，状态保存在浏览器内存中。需要可重复截图时使用固定 preset；正式系统应把配置、审计和执行记录持久化。
